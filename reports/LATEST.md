## 연구 목적
* **이론(Theory)의 가치 측정:** LLM 솔버에게 명시된 이론이 제공될 때 정확도를 얼마나 높이고 추론 비용을 얼마나 절감하는가 [p.1].
* **이론의 유도(Induction):** LLM이 문제들만 보고 스스로 해당 이론을 유도하여, 매번 문제를 풀 때마다 탐색하는 연산 비용을 줄일 수 있는가 [p.1].
* **이론 병합(Merging):** 개별 유도 모델들이 만든 부분적인 이론들을 조합하여 올바른 이론을 생성할 수 있는가 [p.2, p.3].

## 핵심 아이디어 및 방법
* **길이 일치 프로토콜 (Length-matched protocol):** 모든 조건의 컨텍스트 길이를 중립적 텍스트 패딩으로 동일하게 맞춤 [p.1, p.3].
* **회복 비율 (Recovery Ratio, $R$):** $R = \frac{\text{acc}(\text{induced}) - \text{acc}(\text{NOTHEORY})}{\text{acc}(\text{ORACLE}) - \text{acc}(\text{NOTHEORY})}$를 통해 유도된 이론의 성능 향상 복구 정도를 측정 [p.1, p.2, p.4].
* **미발표 이론을 심은 설계 (Planted-theorem design):** 훈련 문제로부터 모델이 이론을 유도하도록 커스텀 확률 가족에 미발표 정리를 심음 [p.1, p.2].
* **코드 탐색 강제 및 검증 분할:** 인듀서에게 작은 인스턴스에서 최소 3회 이상 Python 코드 실행을 요구하며, 검증 분할(validation split)을 통해 최적의 후보 이론을 선택함 [p.3, p.4, p.15].
* **이론 병합 (Theory Merging):** 여러 유도 모델이 찾은 부분적 이론들을 강한 모델이 하나로 병합하여 올바른 이론을 생성 [p.2, p.3, p.8].

## 실험 및 주요 결과
* **데이터셋 구성:** 패밀리 (a) (훈련 40, 테스트 160) [p.2], 색칠 경우의 수 (156개 문제) [p.2], F1(넥클래스, 훈련 30, 보류 60) [p.2, p.14], F2(캐리-오버 스왑, 훈련 30, 보류 62) [p.2, p.14], F3(무작위 충돌, 훈련 30, 보류 60) [p.3, p.14], 그리고 제어군 P5b [p.3].
* **P5b 문제 결과:** 강력한 유도기(strong inducer)가 $R = 0.81$ $[0.67, 0.96]$을 복구하고 힌트보다 +0.24 만큼 앞섰으나, 프로브 응답에 이미 관련 키워드가 포함되어 있어 순수 유도로 보기 어려운 측면이 있음 [p.7].
* **F2/F3 문제 결과:** 
  * F2의 전이 행렬 형태 이론은 궤도 조건이 누락되어 솔버가 복구하지 못하고 held-out 정확도 0.00을 기록함 [p.7].
  * F3의 잘못된 곱셈 공식을 사용한 경우 이론이 없을 때(0.37)보다 낮은 0.01 정확도를 기록함 [p.8].
* **판사 평가:** 블라인드 LLM 판사들의 일치도가 낮아 판사 등급은 기술적(descriptive) 증거에 그치며, 솔루션 정확도가 주된 증거로 활용됨 [p.4, p.5, p.11].

## 한계 및 주의점
* 생성된 군이 적고 합성(synthetic) 데이터이며, 솔버와 인듀서가 단일 가문의 오픈 모델임 (다른 모델 가족이나 확률·조합론 외의 이론에서는 결과가 다를 수 있음) [p.11].
* 심어진 군들이 새로 생성된 것이지만 증명 기법은 교과서적이므로 방법의 부분적 회상을 완전히 배제할 수 없음 [p.11].
* 두 명의 맹검 평가자(blind judges) 간 일치도가 낮음 [p.11].
* 패밀리 (a)의 160개 테스트 문제 중 8개는 훈련 문제와 쌍둥이 관계임 [p.11].
* 각 조건은 3회의 귀납을 사용하여 실행 간 변동성(per-run variation)이 큼 [p.11].

## AI 엔지니어 관점에서 볼 점
* LLM 솔버에게 구조화된 이론(Theory)을 제공하는 것은 정확도 향상과 추론 비용 절감에 큰 잠재력이 있으나, 잘못되거나 불완전한 이론(예: 조건 누락, 잘못된 공식)을 주입할 경우 오히려 성능이 무작위 상태보다 급감(`0.00` 또는 `0.01`)하므로 이론의 검증이 매우 중요하다 [p.1, p.7, p.8].
* 모델이 스스로 코드를 실행(최소 3회 이상)하며 검증 분할을 거쳐 이론을 유도하고, 다중 유도 모델의 부분 이론을 상위 모델로 병합하는 파이프라인은 복잡한 추론 작업을 자동화하는 데 유용한 설계 패턴을 제시한다 [p.3, p.4, p.8, p.15].

**한 문장 핵심 정리:** 본 논문은 LLM 솔버에게 명시적 이론이 주는 가치를 측정하기 위해 제안된 유도·병합 프로토콜과 심은 이론 실험을 통해, 정확한 이론은 성능을 높이지만 결함 있는 이론은 심각한 성능 저하를 유발함을 실증적으로 분석했다 [p.1, p.7, p.8].
